## Design rework after the schematic review (evening)

`docs/schematic-review-2026-09-18.md` found that the QFN20 CP2102N has no DTR, so the
DTR/RTS auto-program circuit could never work, and that GPIO8 floated (needed high for
download boot). Rather than work around it, the USB path was redesigned:

- **CP2102N and its 13 support parts removed** (U4, R11–R13, C9–C11, D6, R18, Q2, Q3,
  R33, R34). USB D+/D− now run from the ESD diode U5 to the module's native
  USB-Serial/JTAG pins (IO19 = D+, IO18 = D−). esptool/ESPHome reset and enter download
  mode over USB by themselves; no buttons needed for flashing. UART0 is broken out on J6.
- **Pull-ups added**: R3 10 k GPIO8, R4 10 k GPIO2, R5 10 k GPIO9/BOOT, R6/R7 4.7 k SDA/SCL.
- **Status LED**: D5 (green) + R14 330 R kept and re-homed to **GPIO7** (active-low), placed
  between the module and the HX711 with a STATUS silk label. ESPHome `status_led` drives it.
- **J6 re-pinned**: 1 = 3.3 V, 2 = GPIO10, 3 = U0TXD (GPIO21), 4 = U0RXD (GPIO20), 5 = GND.
- Board: the five long back-side bus lines between the module and J6 were kept and
  re-terminated (USB pair on the top two, UART on the next two, GPIO10 on the fifth,
  extended to pad 10). GPIO8 and STATUS_LED run down the free channel between the PD_SCK
  and SDA diagonals. I2C/IO2 pull-ups sit in the right-edge strip. 44 parts, 23 BOM lines.
- Firmware: `logger: hardware_uart: USB_SERIAL_JTAG`, `status_led` on GPIO7, pin map updated.

  sockets. SnapEDA `Description_1` junk fields removed everywhere.

  parts group (30 → 27 BOM lines). Legacy KLP-5e `BOM.ods` deleted.

## Regenerating the outputs

```

kicad-cli sch export pdf -o ../fabrication/RevA-<date>/ScaleController_RevA-schematic.pdf ScaleController_RevA.kicad_sch

  -l F.Cu,In1.Cu,In2.Cu,B.Cu,F.Paste,B.Paste,F.SilkS,B.SilkS,F.Mask,B.Mask,Edge.Cuts --subtract-soldermask ScaleController_RevA.kicad_pcb

kicad-cli pcb export pos -o ../fabrication/RevA-<date>/ScaleController_RevA-pos-bottom.csv --side back --format csv --units mm --exclude-dnp ScaleController_RevA.kicad_pcb
```

## Working notes

- Headless copper edits: never use a generic "dangling end" sweep over live areas — a track
  ending on the *middle* of another track (T-junction) looks dangling to a naive endpoint
  test. Delete by explicit coordinates and let DRC's `track_dangling`/`via_dangling` list
  guide the next pass.
- Headless edits to `.kicad_pro` are lost if any KiCad editor is open, even without a
  visible lock — the GUI writes the project file back on save/close. Edit it only when
  the whole project is closed, then check `git diff` after Steve's next GUI save.
- `kicad-cli` on VM 201 has no global symbol/footprint libraries, so ERC shows 85
  `lib_symbol_issues` and DRC shows `lib_footprint_issues` when run outside the project
  dir. Both are environment noise; run from `KiCad project/` for a faithful DRC.
